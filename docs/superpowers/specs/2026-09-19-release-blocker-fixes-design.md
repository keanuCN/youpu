# 发布前稳定性修复设计

## 目标

修复本地全栈验收后发现的两个会影响真实用户数据的问题，并同步完成后台中文显示和验收文档校正。修复完成后再进入数据分析总览开发。

## 方案

### 云端会话同步隔离

API 层维护会话版本号：保存或清除访问令牌时递增版本。同步请求开始时记录令牌和版本；请求返回后只有在两者仍与当前会话一致时，才能写入本地状态或清除会话。登录、注册后的资料水合统一复用该保护路径，避免退出或切换账号后旧响应重新写入账号 A 的资料。同步逻辑保留可注入的请求和状态依赖，便于用延迟响应测试并发边界。

### 产品规范标识映射

对比接口返回的产品以服务端 `item.slug` 建立索引。品牌、型号、年份推导的 slug 只作为本地旧内容的请求引用和回退匹配，不再作为 API 产品的唯一索引，确保规范 slug 与展示模型名称不完全一致时仍能显示收藏、历史和对比记录。

### 后台与文档

举报队列将协议层目标类型映射为中文展示文本，未知值显示为中文兜底；README 将本地迁移、seed 和三服务验收标记为已完成，保留线上部署与未验证流程作为后续事项。

## 验证

- 新增延迟成功响应、过期 401 响应和规范 slug 的回归测试。
- 运行前端聚焦测试、API 健康测试、全工作区类型检查和生产构建。
- 复查工作树、三项本地 HTTP 服务和远端分支状态。
