# 前台目录快照刷新流程

更新时间：2026-09-22

当前线上前台是 Next.js 静态导出，页面默认读取 `apps/web/src/data` 内容包；云端 PostgreSQL 的目录更新不会自动改变已经生成的 HTML。因此每次后台新增或修改已发布产品后，需要在本地重新导出目录快照并构建前台。

`apps/web/scripts/export-catalog-snapshot.ts` 通过公开的 `GET /api/products` 分页读取已发布产品，校验共享 zod 契约后生成 `apps/web/src/data/catalog-snapshot.ts`。快照只保存数据库事实字段：价格、封面、品牌、品类、年份、参数、综合指数和一句话结论。已有本地内容包中的编辑分析、适用人群、评分分布和图集不会被清空；云端新增产品会进入统一 `GEAR` 目录，但缺少的编辑内容明确保持为空。

本地 API 已启动时执行：

```powershell
$env:CONTENT_EXPORT_API_BASE = "http://localhost:3001"
pnpm --filter @youpu/web export:catalog
pnpm --filter @youpu/web typecheck
pnpm --filter @youpu/web build
```

从线上 API 读取时只需要替换地址：

```powershell
$env:CONTENT_EXPORT_API_BASE = "https://xiaopang.club"
pnpm --filter @youpu/web export:catalog
```

注意事项：

- 这是“数据库 → 静态前台快照”的本地刷新流程，不是线上自动部署；构建完成后仍需人工确认再部署。
- API 返回 5xx、契约不符合或分页数量不完整时，脚本会失败并保留原快照，不应强行生成空目录。
- 价格以 API 已归一化的人民币字段为准；脚本也兼容尚未滚动重启的旧 API，将已登记的 USD 按共享汇率换算为人民币；缺少价格时保留为空，不用 0 伪造价格。
- `catalog-snapshot.ts` 是生成文件，后续不要手工编辑；要改数据应修改后台 / 数据库后重新导出。
