## 1. 使用规则

### 状态含义

- `页面已找到`：真实网络环境可以打开官方页面，并能确认产品身份。
- `规格表已找到`：官方页面可看到按尺寸展开的规格表，但仍需逐字段映射到有谱 schema。
- `待回溯年份`：当前官方页存在，但页面对应季节与 YAML 年份不一致，不能直接覆盖 seed。
- `待人工确认`：官方页面入口、产品身份或字段仍不足以完成核对。
- `已核对` 只有在产品季节、代表尺寸、单位和字段逐项对齐后才能使用；本轮暂不把任何 YAML 标记为已核对。

### 每款板必须完成的检查项

- [ ] 确认产品季节、型号、宽版/标准版和性别/人群变体。
- [ ] 保存官方 `source_url`、`crawled_at` 和原始 per-size 表；代表尺寸只是 YAML 展示值。
- [ ] 逐项核对 `length`、`effectiveEdge`、`sidecut`、`waistWidth`、`stanceSetback`、`weight`。
- [ ] 逐项核对 `profile`、`shape`、`core`、`fiberglass`、`base`、`warranty`；品牌技术名保留原文，中文解释另行人工改写。
- [ ] 将品牌硬度量表记录为原始值，再经过人工批准的归一化映射写入 `flex`；不能把不同品牌的 7/10 直接视为同一硬度。
- [ ] `damping`、`pop`、`turnRadiusFeel`、六维 `editorial_scores` 和 `scenes` 由编辑依据证据填写，不从官网宣传文案自动推断。
- [ ] 图片只记录来源和版权状态；官方图片可作为核查证据，不等于获得有谱的转载授权。

## 4. robots 与采集边界

- 12 个品牌的 robots 文件均可访问，但这不等于允许无上限批量抓取。
- Burton、Never Summer、Lib Tech、GNU、KORUA、Bataleon、Arbor、Nitro 等页面明确将购物车、结账、账户、订单或 API/JSON 路径排除在外；采集器只访问公开产品页和公开规格页。
- Jones 的 robots 文件对购物/账户等路径有排除规则；只读取公开产品页，禁止触碰购物、账户和结账路径。
- Salomon 的 robots 文件对多个参数和特定路径有排除规则，产品页核对必须使用干净 URL，不拼接被禁止的查询参数。
- CAPiTA、KORUA、Bataleon、Arbor 的站点还提供 `agents.md`，其中的购物和结账内容不属于本项目范围；本项目只做公开、只读的规格核对，不安装购物技能、不创建购物车、不下单。
- 统一限速按交接文档执行：至少 2 秒/请求；阶段性人工核对优先，不把电商站当成无约束批量数据源。
- 官方图片 URL 只用于溯源和版权审查，不直接作为长期上架素材；正式数据仍需 `source` 留痕并安排授权图、自制图或实拍图替换。

## 6. 尚未实施的技术决策

这些决策来自交接文档，当前只记录推荐方案，不在本底稿中假定为已拍板：

1. **per-size 存档**：推荐将全表保存为 `data/raw/<category>/<brand>/<model>-<season>.json`，YAML 继续保留单一代表尺寸；这样不会丢失尺寸信息，也不迫使前端立即演进 nested schema。
2. **第二品类**：仍推荐羽毛球拍，但应在创始人确认知识兜底后再开始 schema 和 adapter。
3. **flex 归一化配置**：推荐与 `config_rule`/采集层配置中心对齐，保存品牌原始量表和人工批准的映射版本。
