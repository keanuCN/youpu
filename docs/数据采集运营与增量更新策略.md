## 1. 文档与数据文件的职责

采集相关信息不全部放在 Markdown 中。不同文件承担不同职责：

| 文件或目录 | 作用 | 是否作为执行依据 |
|---|---|---|
| `docs/数据采集运营与增量更新策略.md` | 记录流程、目标状态、增量规则和运行记录 | 否，供人理解和维护 |
| `scripts/collector/examples/*-targets.json` | 记录可执行的采集目标 | 是 |
| `data/tmp/collector-*/raw/` | 保存页面原始快照、来源和校验结果 | 是，作为审计证据 |
| `data/tmp/collector-*/drafts/` | 保存通过部分校验的 YAML 草稿 | 否，待审核或自动通过 |
| `data/tmp/collector-*/run-summary.json` | 保存本批目标、耗时、结果计数和输出路径 | 是，作为批次级审计索引 |
| `data/tmp/collector-target-ledger.json` | 保存目标最近状态、成功时间、hash 和差异状态 | 是，作为目标级运行台账 |
| `data/<category>/` | 正式产品 seed | 是，供应用读取 |
| `scripts/collector/README.md` | 采集器命令和当前能力说明 | 否，属于使用手册 |
| `docs/数据采集研究-交接.md` | 研究背景、早期决策和交接上下文 | 否，属于历史研究资料 |

Markdown 记录“为什么采、采什么、怎么判断变化”；JSON 记录“本次具体执行哪些 URL”。这样既方便人工维护，也不会让文档和可执行目标互相脱节。

### 2.1 目标条目要求

每个目标至少包含：

```json
{
  "slug": "brand-model-year",
  "category": "category-slug",
  "brand": "brand-slug",
  "model": "官方型号",
  "year": 2026,
  "url": "https://example.com/product"
}
```

可选字段包括 `identityAliases`、`mode` 和经过确认的 `representativeSize`。型号发生变化、年份发生变化或规格变体需要独立保留时，应创建新的 `slug`，不要覆盖旧目标。

### 2.2 采集优先级

采集顺序按“市场范围 × 产品热度”执行，不按官网是否容易抓取来决定顺序。当前产品策略确定为：

| 优先级 | 阶段 | 采集范围 | 目标 |
|---|---|---|---|
| P0 | 国内热门 | 国内品牌或国内市场热门产品 | 先覆盖中文用户最可能搜索和比较的产品，建立冷启动数据基础 |
| P1 | 国外热门 | 国外品牌热门产品 | 补齐用户认知度高、具有对比价值的主流产品 |
| P2 | 国内产品扩展 | 国内品牌的非热门产品和长尾型号 | 扩大国内品牌覆盖，补足品类目录 |
| P3 | 国外产品扩展 | 国外品牌的非热门产品和长尾型号 | 最后扩展完整度，不影响前两阶段交付 |

这里的“国内”优先按品牌和产品市场归属判断，不简单按网页域名判断；“热门”应有可记录的依据，例如官方旗舰店主推、搜索热度、社区讨论、销量榜单或已有用户需求。没有可靠热度证据时，先标记为待确认，不因为采集方便就提升优先级。

执行规则：

1. P0 未完成前，不主动把普通国内长尾产品排到 P2 之前。
2. P0 的国内热门清单完成后，再集中执行 P1 国外热门；不要在同一批次中混合四个优先级。
3. P2、P3 的目标以“热门清单完成”为进入条件，不要求等到整个市场全部采完。
4. 每个阶段仍按品类分批运行，一次只扩展一个品类，便于校准字段口径和 adapter。
5. 现有 `*-phase1-targets.json` 文件暂时保持兼容；后续新增目标建议采用 `domestic-hot`、`foreign-hot`、`domestic-expansion`、`foreign-expansion` 命名，并在台账中记录优先级。

当前已完成的 Naturehike、Xiaomi、KAILAS 国内品牌批次归入 P0；后续新增国内品牌时，先补热门型号，再进入普通型号扩展。

## 3. 标准采集流程

```text
确定目标
  ↓
更新 targets.json
  ↓
robots 预检与限速抓取
  ↓
保存 raw 页面快照
  ↓
品牌 adapter 归一化字段
  ↓
身份、年份和 partial schema 校验
  ↓
生成 YAML 草稿
  ↓
审计草稿并与正式 seed 对比
  ↓
人工确认或 --auto-approve 写入正式 seed
  ↓
记录本次运行结果、问题和提交号
```

采集器默认只生成草稿，不修改正式 seed。只有完整 schema、页面身份、年份证据和 raw 审计都通过时，才允许进入正式数据；页面被 robots 禁止、跳转到首页、型号不匹配、年份冲突或字段证据不足时，只保留 raw，不猜测字段。

## 4. 运行命令与输出约定

在仓库根目录执行：

```powershell
pnpm.cmd --filter @youpu/collector crawl -- `
  --target-file scripts/collector/examples/tent-domestic-phase1-targets.json `
  --out-dir data/tmp/collector-tent-domestic-phase1 `
  --min-interval-ms 2000
```

输出目录约定：

- `raw/`：每个目标一个 JSON，包含 `capturedAt`、目标、来源、页面快照、adapter 结果和校验结果。
- `drafts/`：通过当前草稿闸门的 YAML，不代表已经发布。
- `failed/` 或 raw 中的失败记录：保留错误信息，便于判断是临时网络问题还是页面结构变化。
- `data/tmp/collector-target-ledger.json`：默认维护每个目标的最近状态、最近成功时间、两个 hash、最近差异状态和预留的下次复核时间；可用 `--ledger-path` 指定位置。

草稿审计示例（可选传入上一批生成的 `diff.json`，得到无变化和更新决策统计）：

```powershell
pnpm.cmd --filter @youpu/collector audit:drafts -- `
  --draft-dir data/tmp/collector-tent-domestic-phase1/drafts `
  --diff-file data/tmp/collector-tent-next/diff.json
```

## 5. 增量采集与更新规则

### 5.1 产品身份

默认用以下组合判断一条产品记录的身份：

```text
category + brand + model + year + variant
```

当前采集器中的 `slug` 是文件和 seed 的稳定入口。后续需要支持多规格变体时，应把尺寸、颜色或套装等变体明确加入身份，而不是依靠产品标题猜测。

### 5.2 页面变化判断

后续增量实现建议为每次 raw 快照计算两个摘要：

```text
rawContentHash       = 页面关键内容的摘要
normalizedSpecHash   = 归一化规格对象的摘要
```

两者的处理方式：

| 情况 | 处理 |
|---|---|
| `rawContentHash` 未变化 | 记录跳过或复核结果，不重复生成草稿 |
| raw 变化但 `normalizedSpecHash` 未变化 | 更新采集时间和 raw 证据，不改正式规格 |
| `normalizedSpecHash` 变化 | 生成新草稿和字段 diff，等待确认 |
| 页面 404、型号消失或跳转首页 | 标记为 `stale`/`blocked`，不立即删除正式数据 |
| 新页面缺少旧字段 | 保留已有有效字段，不用空值覆盖 |
| 年份或型号变化 | 创建新目标和新 slug，不覆盖旧年份记录 |

如果站点提供 `ETag` 或 `Last-Modified`，可以作为提前跳过请求的辅助信号，但不能代替内容校验；很多电商或 Shopify 页面不会稳定提供这些响应头。

### 5.3 状态定义

目标或产品建议使用以下状态：

| 状态 | 含义 |
|---|---|
| `planned` | 已登记，尚未运行 |
| `crawled` | 已生成 raw 快照 |
| `draft` | 已生成草稿，尚未进入正式数据 |
| `audited` | 草稿通过 schema 和 raw 审计 |
| `published` | 已写入正式 seed |
| `stale` | 页面失效或信息疑似过期，待复核 |
| `blocked` | robots、登录、动态保护或网络原因暂不可采集 |
| `retired` | 经确认不再维护，不删除历史证据 |

## 6. 字段覆盖和内容安全规则

1. 新采集页面没有某个字段时，不得用空值覆盖已有有效值。
2. 规格数字必须能在页面快照或官方结构化数据中找到证据；不能根据图片、搜索摘要或相近型号推断。
3. 官网文案只保留必要事实和来源链接，不整段复制营销文案。
4. 图片先保留来源 URL 和采集时间，不因采集成功就默认拥有发布授权。
5. 价格与规格分开更新：价格变化不应生成新的产品身份。
6. 页面改版导致 adapter 失败时，优先修 adapter 和重新生成草稿，不手工修改 raw 证据。

