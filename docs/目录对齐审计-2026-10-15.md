## 六款缺失单板的本地校验与生产阻塞

审计时六款种子对照本地与生产模板均不通过。之后已扩展本地模板并规范化种子；本地全库校验现显示 321 款通过。剩余 16 个字段错误只涉及 5 款运动相机和 3 款电竞键盘，单板种子已无顶层未声明字段。生产仍未更新 schema，因此线上模板尚不接受下列新增的单板字段：

| 商品 | 未声明字段 |
|---|---|
| Donek Knapton Twin Custom | `flexRange`、`sidewall`、`abilityLevel`、`customization` |
| Donek Raven Custom | `flexRange`、`sidewall`、`customization` |
| MOSS Snowstick U4 | `noseWidth`、`tailWidth`、`stanceWidth`、`stanceRange` |
| MOSS Snowstick WING SW 67 | `noseWidth`、`tailWidth`、`stanceWidth`、`stanceRange` |
| NOBADAY Blackboard 6.0 Sky Mirror | `construction`、`brandStyleRatings` |
| NOBADAY Blackboard Pro 5.0 Camber | `construction` |

本地已加入 `flexRange`、`sidewall`、`abilityLevel`、`customization`、`construction`、板头/板尾宽度和站距字段，并完成上述种子值规范化。`brandStyleRatings` 现以明确标注的品牌自评文本保存，避免把不支持的对象结构混入规格；原始 JSON 仍保留结构化分数。`flexConflict` 与 `sizeGuideNote` 已从公开规格移除：冲突原因保留在产品说明和原始证据中，尺码表来源限制保留在原始证据中。COSONE 草稿的 `verificationStatus` 也已从规格移除，待核验状态由草稿状态和说明承载。

`exchangeRate` 与 `exchangeRateSource` 仍是本地隐藏审计字段，需在生产对齐前决定它们是否应公开随商品规格经 API 返回。

## 逐尺码表字段规范化进展

盘点 602 条单板尺码行后，本地 `sizeSpecs.itemSchema` 已从原有字段扩展为 98 个已用键，类型涵盖数字、文本、布尔值、数字范围、数字/文本混合值和型号版本对象；当前数据未发现未声明行键。前台补充厘米、英寸、毫米的来源别名，显示时保留来源单位；范围显示为上下限；KORUA 的不同表面重量、最大适配欧码会分别标明来源版本。NOBADAY 两款小黑板可展示有效长度、侧切半径和推荐固定器尺码。

生产 schema 尚未同步本地新增字段；此前生产审计记录的 `sizeSpecs.itemSchema` 为 30 个键。本地变更扩大了字段集，需在生产同步前生成精确差异并审核，不写入所有 98 个字段作为默认要求。商品 API 的 `sizeSpecs` 行键校验目前仍只校验已声明字段的类型，不拒绝未知键；本轮全量数据审计确认当前没有未知键，后续可将未知键检测纳入审计器。

## 全站未声明字段审计

初始审计在 329 个种子中发现 37 次顶层未声明字段。更新本地单板契约并清理草稿备注后，当前剩余 16 次：运动相机 10 次、电竞键盘 6 次，涉及 8 款商品的 `priceSource` / `priceStatus`。本轮全库验证结果为 321 款通过、8 款因上述字段未声明而失败；滑雪商品均通过。价格来源字段属于全局价格来源建模问题，暂不随滑雪目录更新一起处理。
