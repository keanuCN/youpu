# M2 后台基础版实现记录

> 更新时间：2026-09-16

## 已实现

- `apps/admin`：Next.js 静态管理端，默认端口 `3002`。
- `/api/admin/*`：NestJS 管理 API，统一由 Bearer 管理令牌保护。
- 总览：产品、草稿、发布、品牌、类目数量与最近更新。
- 产品：搜索、状态筛选、详情编辑、新建草稿、发布状态、价格、来源 URL、图片 URL。
- 操作审计：后台写入产品、品牌、类目和审核状态时记录操作人、动作、对象及前后快照，后台提供筛选查看。
- 内容质量概览：总览展示缺图片、缺价格、缺来源、缺编辑评分数量，可点击进入产品补齐队列。
- 动态参数：产品表单根据类目的 `spec_schema.fields` 自动生成，number / enum / enum[] / nested / bool 均有对应输入方式。
- 品牌：创建、编辑、启停、产品数量查看。
- 类目：创建、编辑、父子层级、排序、启停、`spec_schema` 与 `recommend_config` JSON 校验。
- 数据质量：产品写入前复用 `packages/schema` 的 `parseSpecSchema` / `validateSpecs`，并写入 `product.updated` outbox 事件；产品列表支持按缺图片、缺价格、缺来源、缺编辑评分筛选，并展示资料状态标签。

## 本地启动

1. 复制 `apps/api/.env.example` 为 `apps/api/.env`，将 `ADMIN_TOKEN` 替换为至少 16 位随机令牌。
2. Docker 可用时执行迁移与 seed。
3. 启动 API 与管理端，打开 `http://localhost:3002`，输入同一个管理令牌。

M2 当前是单人内测鉴权，不是多账号 JWT 系统。账号、细粒度角色、COS 直传、批量文件导入和榜单编辑仍属于后续批次；审计日志已提供本地基础版，正式环境仍需接入真实操作账号和请求 IP。

## 管理 API

| 方法 | 路径 | 用途 |
|---|---|---|
| `GET` | `/api/admin/auth/me` | 验证管理令牌 |
| `GET` | `/api/admin/dashboard` | 总览统计 |
| `GET` | `/api/admin/audit-logs` | 操作审计记录，可按对象 / 动作筛选 |
| `GET/POST/PATCH` | `/api/admin/products` | 产品列表、新建、更新；列表可用 `missing=image|price|source|scores` 筛选缺口 |
| `GET/POST/PATCH` | `/api/admin/brands` | 品牌列表、新建、更新 |
| `GET/POST/PATCH` | `/api/admin/categories` | 类目列表、新建、更新 |

所有写接口使用共享 zod DTO，并拒绝未声明字段，避免 mass-assignment。
