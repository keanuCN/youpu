## 1. 项目背景（30 秒版）

- **有谱（youpu）**：中文装备选购站 = 结构化参数图鉴 + 横向对比 + 按条件推荐 + 社区实测。首发品类滑雪单板，架构按多品类设计（新增品类 = 类目配置 + 录数据，零代码改动）。
- **现状**：M1 脚手架完成；前端全部页面落地（内容包 + localStorage 架构）；SEO 技术包完成；内测站已上线（http://111.229.87.101/ ，静态导出 + nginx，已备案津ICP备2026009482号，域名 xiaopang.club 待解析）。
- **里程碑**：M2（列表/详情接 API + ES + 后台基础 + **40 款数据**）准备就绪、接入未开始。
- 详细见 `README.md`、`docs/有谱-技术设计方案.md`（采集相关：§3 Crawlee 选型、§4 scripts/ 目录规划、§16.3 后台导入工作台）。

## 2. 本研究的任务定义

研究"网站所需专业数据的爬取工作"：要采什么、从哪采、怎么合规地采、用什么管线采，并按多品类（自行车 / 钓鱼 / 摄影 / 羽毛球拍）扩展设计框架。

## 3. 核心结论

### 3.1 一条可上架记录 = 五类数据，可爬性各不相同

| 类别 | 字段 | 可爬性 |
|---|---|---|
| A. 几何参数 | length / effectiveEdge / sidecut / waistWidth / stanceSetback / weight / warranty | ✅ 品牌官网 per-size 表直接有；weight 最常缺 |
| B. 结构文案 | profile / shape / core / fiberglass / base / turnRadiusFeel | ⚠️ 可抓原文，需人工改写中文口径；profileFamily 由 `profileFamilyOf()` 规则派生 |
| C. 性能数值 | flex / damping / pop / scenes | ❌ 人工为主（官网无 damping/pop；flex 各品牌量表口径不一） |
| D. 编辑评分 | editorial_scores 六维 | ❌ 人工判断，创始人兜底；The Good Ride 的 1-10 量化分可作参考 |
| E. 图片 + 价格 | images（base/face/side/field）、price CNY | ⚠️ 图片可爬但有版权问题（见 3.3）；CNY 价格人工录 + 月度核对，自动化走京东联盟 API |

### 3.2 一个待拍板的 schema 决策点

官网/evo 给的是 **per-size 完整表**（每个长度一行），当前 spec_schema 的 specs 存单一代表值。建议：采集层把 per-size 全表存进 raw JSON 草稿存档，YAML 只填代表尺寸；技术方案 §5 本就预留了"尺寸表 nested"演进路线，数据先攒不吃亏。

### 3.3 合规红线（不可妥协）

1. 只爬公开页面：不登录、不破解验证码、不绕反爬技术措施（中国司法实践里刑事风险集中在"绕过技术措施"）。
2. 遵守 robots.txt + 限速 ≥2s/请求；品牌官网通常宽容，电商大站（evo 等）只做零星人工查证，不批量爬。
3. 参数数值是事实（不受著作权保护），但品牌文案/评测文字/图片受保护：评测文字绝不整段搬；图片走既定策略——来源字段强制留痕（§16.2 已设计）→ 详情页标注 → 长期替换授权图/自制图。
4. 抓取原始数据（含 source_url、crawled_at）随草稿存档，可追溯。

### 3.4 采集框架：品类无关引擎 + 品类适配包

管线（Crawlee → raw JSON → 归一化 → zod 校验 → YAML 草稿 → 人工 diff → 导入）本身无品类逻辑，每品类不同的只有四样：spec_schema 定义、品牌 adapter、归一化映射表、人工校对。目录规划：

```
scripts/collector/
├── engine/                    # 品类无关，一次写好
│   ├── crawler.ts             # Crawlee 双引擎（Cheerio 静态 / Playwright 渲染兜底）
│   ├── jsonld.ts              # 通用 JSON-LD Product + 常见规格表 pattern 提取
│   ├── draft.ts               # raw → 归一化 → 按类目 spec_schema zod 校验 → YAML 草稿
│   └── images.ts              # 图片：webp 压缩 → COS 直传 → source 留痕
└── categories/<category>/
    ├── schema.yaml            # 该品类 spec_schema（来自 data/categories.yaml）
    ├── normalize.ts           # 单位/量表映射（如 flex 归一，人工校准表）
    └── brands/<brand>.ts      # 品牌 adapter：只负责找对页面 + 特有解析
```

关键设计约束：
- adapter 解析结果必须过 zod spec_schema 校验（与 `pnpm --filter @youpu/api validate:data` 同一契约），官网改版时硬失败而非脏数据入库。
- flex 量表归一必须人工拍板映射表（各品牌 7/10 不可直接横比），这本身是内容护城河。
- 在本地开发机跑（服务器只有 1G 内存）；雪季前集中跑 + 每周一批，无常驻服务。
- 全品类复用三件套：zod 校验闸门、京东联盟价格 API（`jd.union.open.goods.query` 不分品类，已备案是现成门槛）、图片管线。

### 3.5 数据源地图

**单板（12 品牌已 seed 15 款）：**
- 第一来源：品牌官网 per-size 规格表。Burton 已验证（官网产品页按长度列 running length/waist width/每档推荐体重，另有官方 sizing disclaimer 汇总页）；Jones/CAPiTA/Lib Tech/GNU/Nitro/Salomon/Ride/Never Summer/Bataleon/Arbor/Korua 均有 Tech Specs/Sizing 表，多数是 Shopify 系模板（HTML/JSON-LD 可解析），部分需 JS 渲染。
- 交叉验证：evo（产品页有 per-size Specs，已验证）、The-House、Backcountry、Blue Tomato。只作兜底与核对，不批量爬。
- 补 weight 实测：Snowboard Robot（独立称重，待人工核实网站现状）；board-insight.com（德语多点几何，待核实）。
- 编辑评分参考：The Good Ride（已验证，按 flex/damping/playfulness 等类目打 1-10 量化分，与本站六维同构）；Whitelines / Angry Snowboarder / Snowboarding Profiles 只作人工判断输入。
- 人查工具：snowboard-length-calculator.com（按品牌/型号/年份整理规格页，已验证）。

**其他品类：**
- **羽毛球拍**（推荐第一优先扩展）：参数最简（重量 U 分级 / 平衡点 / 中杆硬度 / 拉线磅数等约 8-10 字段）；三大品牌 YONEX/Victor/李宁官网即覆盖主流；中羽在线装备库（bbs.badmintoncn.com/equip.php，已验证）资料最全但形态是论坛帖，"图鉴+对比+推荐"产品形态空缺。
- **钓鱼·台钓竿**（第二顺位）：字段简单（长度/自重/先径/元径/调性/节数/收缩长/含碳量）；禧玛诺/达瓦中国官网有官方中文参数（待核实）；中文参数站质量参差（待核实）；**子品类爆炸风险**——先收窄"台钓竿"单叶起步。
- **自行车**（成本最高，最后做）：车架几何 per-size 表（Stack/Reach/头管角/轴距等）与单板同构但字段更多；**SKU 爆炸是本质难点**（一个车系 N 配置 × N 尺码），需先拍板"以车型为录入单位"；形态参照 99spokes.com / geometrygeometry（待核实）；中文无结构化对比产品（美骑是媒体形态）。
- **摄影**（参数最好爬但红海）：厂商官网参数最标准化（镜头含 MTF），DxOMark 量化评分可参考；但中文竞争激烈（ZOL 产品库 detail.zol.com.cn 已验证是十几年红海），只建议作为"验证多品类管线"的练手品类。
- **价格（全品类通用）**：京东/天猫旗舰店人工录价 + 月度核对（v1 几十款够用）；自动化走京东联盟 API（个人可注册、站点需备案——本站已备案是现成优势），建议后置到做导购链接时。

### 3.6 品类优先级评估矩阵

| 维度 | 单板 | 羽毛球拍 | 钓鱼·台钓竿 | 自行车 | 摄影 |
|---|---|---|---|---|---|
| 参数结构化 | 高 | 高 | 高 | 中 | 极高 |
| 数据源可得 | 高 | 高 | 中 | 中 | 极高 |
| 中文竞争空窗 | ✓ | ✓ | ○ | ○ | ✗ |
| 品牌覆盖成本 | 12 品牌 | 3 品牌 | 2-3 品牌 | 15+ | 10 |
| 冷启动 | 中 | 低 | 低 | 中 | 低-中 |
| **创始人知识兜底** | ✓ | ？ | ？ | ？ | ？ |

决策第一变量是最后一行（设计文档既定原则：品类编辑兜底数据质量）。其他维度支持羽毛球拍先上，但若创始人对别的品类更熟，熟悉度优先。

## 4. 已定 vs 待决策

**已定（设计文档既有，执行即可）：**
- 采集用 Crawlee（§3 选型），脚本进 `scripts/`（§4 目录规划）。
- 管线：采集 → YAML 草稿 → 后台导入工作台预览 diff → 确认入库（§16.3）。
- 图片版权策略：source 留痕 + 详情页标注 + 长期替换（§11 / §16.2）。

**待决策（动手前需拍板）：**
1. per-size 全表存档方式（raw JSON 草稿 vs 直接上 nested 字段）——见 3.2。
2. 第二品类选谁（建议羽毛球拍，最终看创始人熟悉度）。
3. flex 等量表归一的映射表放哪（建议 `config_rule` 表 / 采集层 config，与 §16.2 配置中心对齐）。

## 5. 建议执行顺序

| 阶段 | 内容 | 工作量 |
|---|---|---|
| **Phase 0（最先做，零代码）** | 人工把已有 15 款板参数逐项对官网校对——**样例 YAML 头部就标注"参数未经官网逐项校对"**；顺手确认 12 品牌字段可得性，留档 per-size 表 | 1-2 天 |
| Phase 1（M2 内） | collector 骨架（engine/）+ 首批 3 个 adapter（建议 Burton/Jones/CAPiTA，覆盖 5 款）+ 草稿→校验→diff→导入全链路 | 骨架 1 天 + 首个 adapter 1 天 |
| Phase 2（M2 出口前） | 补齐 40 款（约 12 个品牌 adapter） | 0.5 天/adapter + 人工校对 15-30 分钟/款 |
| Phase 3（运营期） | 每周 5 款节奏；Snowboard Robot 补 weight；京东联盟 API 刷价 | 按周滚动 |

40 款全链路（采集+校对+图片+价格）约 5-7 个工作日。多品类节奏约束：**一次只开一个新品类**；闸门条件 = 老品类周维护 <1 天；新品类标准流程 = 定 spec_schema → 人工试录 5 款校准口径 → 再写 adapter（顺序别反）。

## 7. 证据可信度与环境限制（重要）

- 本环境**无法直连境外网站**（TLS 被重置，WebFetch/curl 均失败），外部验证依赖搜索快照。
- 标注"已验证"= 搜索快照确认（Burton per-size 表、evo Specs、The Good Ride、中羽在线、ZOL、京东联盟 API 门槛）。
- 标注"待核实"= 仅模型知识佐证，**动手前必须人工开站确认**：Snowboard Robot 现状、board-insight.com、99spokes.com、geometrygeometry 域名、各钓鱼参数站、禧玛诺/达瓦中文官网参数表。
- 开工第一步建议先跑一遍真实网络环境下的数据源核实（本报告待核实项 + 每品牌 robots.txt）。
